# Qwen3.5 2B、4B 与现有 2.5-3B 的本地语音对照

2026-11-04，Apple M4 Pro、24 GB 统一内存，Ollama 0.32.15。两款模型已下载并通过官方仓库文件 SHA-256 校验，默认语音模型仍为 `qwen2.5:3b`。本轮没有修改默认配置、重启本地服务、访问 ECS 或调用云端模型。

当前机器继续保留 3B 更符合低延迟实时对话的要求。2B 的中位响应更慢，本批题的事实、记忆和表达问题更多，没有显示出替换优势。4B 在本批缺失信息、记忆和例句题上较稳，但首音中位数增加约 673 ms，仍有不适合直接朗读的音标和中文校验拒绝问题，适合作为质量优先的后续候选。

## 速度

| 实际下载版本 | 模型请求首段文字 P50 / P95 | 英语录音首段 PCM P50 / P95 |
| --- | ---: | ---: |
| Qwen2.5-3B，Q4_K_M | 272 / 938 ms | **406 / 938 ms** |
| Qwen3.5-2B，Q8_0 | 380 / 716 ms | 609 / **768 ms** |
| Qwen3.5-4B，Q4_K_M | 863 / 1,195 ms | 1,078 / 1,359 ms |

文字统计只使用实际调用模型的请求，每模型 64 次；规则直接回答单独保留。语音统计使用相同的 12 条英语录音、两轮，每模型 24 次，全部生成 WAV。2B 在本批尾延迟上优于 3B，但中位速度与回答质量没有同时改善。不能把表解释为所有延迟指标都由 3B 胜出。

**首音从完整输入录音及其结束边界已经可用时计到首段 PCM 就绪**，包括 Parakeet 识别、当前语音 Bot、正常语音分段和 Kokoro MLX 合成。它不包含现场 VAD 等待、麦克风采集、WebSocket/浏览器传输或扬声器缓冲，不能当作真实麦克风到扬声器的出声延迟。模型加载及预热不计入热请求；ASR 中位耗时分别约 62、61、65 ms。

三款均通过现有 Ollama 适配器设置 `think=false`、温度 0.3、4096 上下文、最多 256 输出 token。Kokoro 速度 0.95、音量 0.2，精确音频缓存关闭。所有请求串行，模型生成与排队的 TTS 保留正常重叠。模型块次序为 ABC / CBA，题目固定种子乱序；每块前预热并卸载其他候选。

2B 的官方默认标签是 Q8_0，3B、4B 是 Q4_K_M。这是所下载版本的实际选型比较，没有控制量化精度，因此不能从结果直接推断同精度的 2B 一定比 3B 慢。Ollama 展示的下载体积约为 2.7 GB 和 3.3 GB，包含对应资源。

## 回答内容与录音复核

任务题为 24 个场景，每模型两轮，共 48 条交付文字。另保留 40 条既有回归题、每题两轮。前两条任务题曾用于评测工具冒烟检查；这不是独立教师盲测，也不是代表真实儿童会话的随机样本。

逐条助手复核检查主要事实、所请求内容、指定语言及英语示范是否可交付；明确错误判失败，未核实的扩展解释或指代歧义单列待复核。套话、额外追问和长度等风格问题保留在规则评分中，不与事实错误混为一类。

| 任务题交付文字，48 次/模型 | 通过 | 失败 | 待复核 |
| --- | ---: | ---: | ---: |
| 2.5-3B | 39 | 7 | 2 |
| 3.5-2B | 30 | 16 | 2 |
| 3.5-4B | 44 | 2 | 2 |

逐条记录见 [text-review.json](../evals/local_voice_models/text-review.json)。这是本批交付件的助手判断，不能当作模型总体准确率。相同问题的两次请求也不是独立样本。

所有 72 份英语输入对应的回复 WAV 均核验 SHA-256、16 kHz 单声道 PCM16、非空及非零 RMS，再使用独立 Whisper-large-v3-turbo 转写核对内容。八份中英混合/中文输出另外强制中文转写，保留两种转写，避免静默选择有利结果。未组织真人听音或 MOS 测试。

录音复核结合交付文字和独立转写；转写的不确定项没有算作通过，不能将表解释为真人听力评分。见 [audio-review.json](../evals/local_voice_models/audio-review.json)、[完整波形验证与转写](../evals/local_voice_models/audio-verification.json)。

具体差异：

- 题目只说 Iris 周六去了公园，没有同行者。4B 两轮都明确说原文没有说明；3B 一轮重复问题，另一轮编出家人；2B 分别编出“没有名字的人”和朋友们。
- 已明确更新为乘公交去学校后，3B、4B 的文字题两轮均正确，2B 两轮仍答步行或骑车。2B 一条录音回复甚至说用脚、手、腿和嘴去上学。
- 2B 两轮文字解释均编造龟壳用于放蛋；一条录音又把鸭子与猫都称作哺乳动物。它也多次使用 `wear an umbrella`，不适合直接作为英语示范。
- 3B 一次录音回答声称用户的 rabbit 发音正确，尽管 Bot 实际只收到了转写；另一轮正确说明不能听音。4B 两次都正确说明能力边界，但一轮输出 IPA，使 TTS 读出 `slash`、`stress`、`small cap` 等符号名称，这条录音仍判失败。
- 4B 任务题两次 `big/small` 请求都被中文交付校验拒绝，额外英语例句已经生成也不等于成功交付。三款都有需要区分模型内容与应用校验的问题。
- 部分中文混合录音的自动语言转写出现中文拼音化或内容遗漏；强制中文能恢复 4B 的 cherry 释义，但未稳定恢复两份 3B 混合长回复。波形保留待人工听辨，不能仅靠非零振幅认定语音内容正确。

## 规则结果与边界

全部 128 次文字 Bot 请求的规则通过数为 111、110、117；其中 80 次既有回归请求分别为 78、75、79。文字未交付为 2、4、3 次，均为应用的中文校验拒绝，不能称作模型接口故障。

规则会把正确的翻译问号误判成主动追问，也会因为正确回复回顾了旧的 bike 事实而触发禁词；反过来，含有正确关键词的编造同行者或错误生物常识可能通过。规则评分没有在正式运行后修改；因此内容判断使用独立的逐条复核，原始规则结果全部保留。

每款另有三条中文输入、两轮。18 次中文探针全部被当前英语 ASR 的置信度门槛拒绝，没有进入语言模型。换 LLM 无法解决这一批中文输入未进入对话的问题。它们单列，不混入英语首音统计或英语录音质量排名。
