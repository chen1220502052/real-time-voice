# 单元作文与教材词汇

章节页 `/practice.html` 的“跟读、听力、口语”旁新增“作文”。可以自己写、查看 AI 点评，或先找网上范文；独立页面为 `/writing.html`。沿用当前账户和教材选择。

## 运行

```bash
python3.11 -m pip install -e '.[writing,dev]'
./scripts/run_text.sh
```

使用已有 `DEEPSEEK_API_KEY` 或 `LLM_API_KEY`。写作模型依次读取 `WRITING_MODEL`、`LLM_MODEL`，默认 `deepseek-flash`；写作端点默认 DeepSeek，可用 `WRITING_BASE_URL` 覆盖。检索、视觉识别及点评使用 DeepSeek 官方接口。
独立环境可通过 `PYTHON_BIN=/绝对路径/venv/bin/python ./scripts/run_text.sh` 启动，不改动现有语音环境。

## 教材词表

科普版现有 4–9 年级共 12 册、94 个单元的 112 张词表图片已识别整理。先整页识别与复核，再对全部 28 张跨单元边界页面独立分栏识别，保留两个层次的原始结果。最终保留 3,557 条去重后的单元词汇/短语；剔除了被 OCR 误当成单词的续行词性标签，跨页中文释义不作为词汇。

新词表不包含全部早年基础词，因此另从四年级上册各单元最前面的 2–3 张实际课文图片（共 35 张）提取已经出现的对话、故事和图片标注中的词。每个词都有出现单元和原图依据；不采纳无标注图片猜词，不添加默认基础词，不把教师练习指令和原创主题补充词当作已学词。此部分是保守补充，并非全部课文的完整词汇转录。

数据见 `英语/科普版/结构化教材词表.json`，原图清单、双轮结果、分栏结果、课文词汇证据及纠错记录见 `backend/data/curriculum/`。详见 [词表来源与核查](21-curriculum-vocabulary-audit.md)。

- 词汇从当前教材系列的四年级起按年级、册次、单元数字累计，包含当前单元，排除后续单元。
- 五年级上册 Unit 10 为 Revision，没有独立新词页，使用之前的 34 个单元累计词汇，不虚构新词。
- 七年级下册从 Unit 7 开始，八年级旧版下册从 Unit 5 开始，不把编号起点误判为缺页。
- 初中旧版和新课标版不自动混合。旧版部分前序册次目前缺失时，仅使用已有来源的较小范围，页面列出缺失项，点评不计算词汇分。
- 人教版现有资料没有完整词表原图。仍可练习和保存草稿，但不再用原创主题词表冒充完整教材词表来生成/点评。可以选择科普版或导入对应词表。

`WRITING_VOCABULARY_FILE` 仍支持手工核对词表覆盖，使用版本 1 JSON：`{"version":1,"foundation":[],"chapters":{"章节ID":{"words":["apple"],"source":"教材页码与核对说明"}}}`。未指定 foundation 时为空，不暗中放行一份基础词表。聊天和写作现共用该配置；若同时设置 `CHAT_VOCABULARY_FILE`，两者统一优先使用后者。

## SQLite 累计词汇缓存

写作选单元、生成范文和批改均通过 `chat_library().scope(chapter_id)` 读取与聊天相同的 SQLite 快照，不再保留启动时的单元目录或每次重新合并词汇。数据库路径由 `CHAT_LIBRARY_DB` 指定，默认与 `ACCOUNT_DB` 同目录的 `chat-library.sqlite3`，独立于账户和私人对话数据库。`unit_words` 保存单元词，`cumulative_words` 保存按学习进度合并的词；章节快照保存问题、累计集合和来源摘要。

每次请求检查词表及覆盖文件的内容版本，内容哈希按文件状态缓存。同长度替换、删除词和恢复旧版本都会被检测；版本变化时在临时 SQLite 文件中重建完整数据，成功后原子替换。无须重启服务。损坏的导入不覆盖原数据库，对应请求报错，修好源文件后恢复。部署环境继续只使用一个工作进程，线程内的构建锁合并同时到达的重建请求。

累计词汇以不可修改的内存集合缓存，常见词形只在加载快照时展开，生成与批改通过集合判断词汇。章节元数据、词表和来源返回副本，避免调用方污染缓存。更新时新请求读取新快照，正在生成或批改的请求继续使用其已取得的同一版快照。SQLite 重建和读取在线程中执行，避免阻塞异步接口。建议原子替换源 JSON，避免读取到编辑中的半份文件。

## 范文

默认先调用 DeepSeek Search，查询只含公开教材版本、年级和单元主题，不发送学生作文、账户名或私人信息。标题/摘要不足以判定找到范文：只有取得实际网页内容，并找到主题相关、句子完整、长度与词汇均通过检查的短文段落，才优先展示来源链接和不超过 20 词的节选，全文留在原网页。

没有合适段落、取不到正文或检索失败时回退为 DeepAgents + DeepSeek 原创范文。学生页统一使用“生成范文”按钮，自动检索或生成；区分范文节选和 AI 范文，节选保留原文链接。

AI 范文优先保证表达自然、内容连贯，用已学词汇表达一个清楚的中心，避免凑词、无关细节和机械重复。必要时允许少量新词：标题和正文一起检查，默认最多 4 个不同表外词、出现次数比例不超过 5%，这是上限而非配额；API 仍支持零表外词。目标 30–300 词、长度允许上下浮动 20%。识别常见词形及缩写，词形规则不是完整语法分析。

每篇初稿即使词汇检查通过，也必须再由模型进行一次全文审读和润色，检查主题、细节、搭配、指代及衔接。词汇工具不再要求删除所有表外词；超限时优先简化内容或自然改写。最多三次模型调用（含初稿、润色和必要的进一步修订），服务端对润色结果重新检查词汇、长度和新词释义，仍不合格则报错。自然度与连贯性由模型审读改善，并非确定性的质量保证。

## 学生作文与点评

学生输入标题和正文，点击“批改作文”。页面保留建议分、优点、改进建议和逐处修改说明，隐藏词表来源、校验统计和技术说明。每条纠错必须引用学生原文真实存在的连续片段，服务器拒绝捏造引用；不替换学生原文。点评同时关注自然表达和连贯性，少量必要新词可保留。建议分不是正式考试成绩，缺少前序词表时词汇分不计入总分。

草稿按账户 ID 和章节 ID 保存在浏览器本机，切换章节、刷新可恢复；页面明确说明没有跨设备草稿同步。学生原文会发送给已配置的 DeepSeek 完成点评，不写入服务端聊天记录。

## 接口与验证

- `GET /api/writing/scopes/{chapterId}`：累计单元、词汇量、原图链接、覆盖状态、缺失册次。
- `POST /api/writing/compositions`：`chapterId`、`instruction`、`wordCount`、`strict`、`searchFirst`。
- `POST /api/writing/reviews`：`chapterId`、`title`、`essay`、`instruction`、`wordCount`。
- `GET /api/practice/vocabulary-pages/{pageId}`：仅提供已索引原图，受账户认证保护。

错误分别报告非法输入、容量不足、检查不通过、资料不可用、模型不可用和超时；模型异常不会原样暴露。所有昂贵任务复用现有资源容量限制，取消/失败时释放容量。
