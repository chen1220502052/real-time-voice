# 3B 文字聊天与短范文对照

本轮在同一台机器的本地 Ollama 对比 `qwen2.5:3b` 和 `qwen3.5:9b`。没有微调、部署、切换产品默认模型或使用学生记录。模型分别预热，样本分两半反转模型次序，串行单请求。各模型每题一次，保留实际默认采样温度，结果适合本地试点判断，不能当作总体质量估计。

文字聊天走真实的自由聊和教材聊机器人。两条路径在查库/调用模型前处理证据充分的偏好、Kitty 的真实身份及教材词义；有例句等附加要求时把词义当作参考交给模型继续完成。评测以同一份聊天代码测试两个模型，教材机器人使用真实单元词表，不连历史记录库或检索库，以隔离模型和规则效果。首段是机器人发出的首个文字事件，不包括浏览器、账号、网络或语音处理。

短范文是独立的原创题集，来自 3–6 年级八个本地已核对单元的主题，每题 30–65 词。八题各用自然表达和教材限词，另选四题用零超纲，共 20 个请求/模型。走现有范文服务与真实字数/词表/释义检查，关闭网上范文检索和写作思考模式。评测按服务是否交付与交付后逐篇审阅分开；审阅看题目要求、行文与标题、语境释义。审阅是同一评审者逐项判断，未做双人盲审。没有测试学生作文的批改或打分。

自然表达模式最接近本轮设想的短范文场景。3B 交付 3/8，9B 交付 7/8；请求耗时中位数（含失败）为 3.10 秒和 11.43 秒。仅看交付件，分别为 4.28 秒和 12.26 秒，但这是不同的成功子集。3B 有 5/8 用完两次重写仍未交付，9B 有 3/8 走到第二次重写，其中两份成功。3B 多次改写后仍维持原有短度，例如 40 词的动物园题三份草稿都是 23 词（最低 32 词）；两份通过字数检查的成品把 `English title` 当标题，另一份把 `have a good time` 中的 `have` 释作“有”。

教材模式的首次重写是固定的审稿步骤；只有第二次才是额外重试。自然模式没有强制审稿重写。释义可能有独立模型调用，计入耗时而不计为重写。截断请求没有交付，首次评测未记录其已完成的改写数，因此标为缺失。

| 文字聊天，24 题/模型 | 3B | 9B |
| --- | ---: | ---: |
| 规则直接回答，内容与格式通过 | 12/12 | 12/12 |
| 模型回答，语义通过 | 10/12 | 8/12 |
| 模型回答，语义及格式均通过 | 7/12 | 7/12 |
| 模型回答，首段文字中位耗时 | 217 ms | 1,458 ms |
| 模型回答，完成中位耗时 | 258 ms | 1,582 ms |

模型回答中，3B 正确给出 peach 的中文释义和例句，但问 Kitty 是否喜欢下雨时反问用户；三条翻译或例句回复未闭合引号。9B 在自由生成里把喜欢蓝色升级成最喜欢蓝色，说明直接处理的覆盖范围不等于整个聊天流程都消除了该错误。两款模型在这批题中都没有编造 Kitty 的年龄。所有聊天请求均正常结束。

| 短范文 | 3B | 9B |
| --- | ---: | ---: |
| 自然表达，服务交付 | 3/8 | 7/8 |
| 教材限词，服务交付 | 0/8 | 2/8 |
| 零超纲，服务交付 | 0/4 | 0/4 |
| 三项质量审阅均通过（按全部请求计） | 0/20 | 5/20 |
| 教材限词，全部请求耗时中位数 | 18.74 秒 | 13.77 秒 |
| 两次重写（全部模式） | 13/16 次可计 | 14/20 次可计 |

3B 四次教材限词请求因模型输出截断结束，最长约 65 秒。9B 仍常因限词等校验失败；严格模式的失败不支持更换模型，也不表明 9B 已经适合稳定交付零超纲范文。

建议先保留现有默认配置。文字聊天的 3B 可作为下一步小范围试点，优先普通对话和课内问答，补测长对话、中文附加要求及例句的输出边界后再考虑设为默认。作文保留 9B，并优先修正限词策略和生成后的内容检查；这一轮没有证据支持把短范文切到 3B。

复现脚本：`scripts/evaluate_text_and_writing.py`。原始输入、逐次模型输出、耗时和审阅分别在 `evals/text_chat/` 与 `evals/short_essay/`。相关回归测试 104 项通过、1 项跳过。
