# 本机端到端语音模型对照

2026-11-04，在 Apple M4 Pro、24 GB 统一内存上，对照现有 Parakeet int8 → Qwen2.5-3B → Kokoro MLX，以及 Qwen2.5-Omni-3B、MiniCPM-o 4.5 Q4_K_M。测试对象是本机可运行的完整方案。

当前 Mac 上，英语实时陪练优先保留现有分段链路。MiniCPM-o 4.5 的本机首音更慢，偏好与中文身份错误仍在。Qwen 的本机 MPS 声码器未通过音频内容核验，CPU 声码器回退能恢复语音，响应时间仍难以用于当前对话。

## 测试口径

题集含 12 条英语语音和 3 条中文语音，每条两轮。英语题覆盖 AI 年龄与生日、喜欢与最喜欢、偏好更新、中文词义与例句、语境词义、历史记忆、邀请句、虚构人物、短句追问与换题。输入由 macOS Samantha 和 Eddy 离线合成，没有使用学生录音。历史对话以文字提供，最新问题仅提供语音。源音频和输出音频均保存在 .local/omni-eval/。

首音指标从完整输入音频及其结束边界已经可用时开始，计到第一段 PCM 可用。计入预处理、识别、模型和合成，预热单列。指标没有覆盖现场 VAD 等待、麦克风传输和扬声器缓存。速度表使用两轮相同的 12 条英语输入，中文输入能力另外检查。

现有链路保留事实与词义处理，使用正常语音分段，关闭精确音频缓存。MiniCPM 使用 Metal 和真实流式 PCM 回调。Qwen 使用 Transformers/MPS 的完整波形返回接口，首音包含等待整段波形生成的耗时。本轮没有测量其 NVIDIA 流式部署。

使用独立 Whisper-large-v3-turbo 转写实际输出，以核对语音中的内容。转写有误差，审阅保留原始文字和 WAV，没有进行真人盲听或 MOS 打分。中文样本 o13 中的英文 peach 被独立转写识别成 perch，存在合成发音歧义，因此该题保留运行记录并排除质量计分。

## 运行与接入记录

两款模型的权重固定到 Hugging Face 提交版本，分块续传后核验官方 LFS SHA-256。Qwen 主语言模型名称中的 3B 对应其语言部分，完整语音及视觉权重包含约 55.4 亿张量元素，官方文件约 12 GB。

MiniCPM 官方 C++ 服务的本机测试副本有两处小修正。服务监听使用传入的 loopback 地址，语音输出模板使用传入的系统提示词。编译使用 LLAMA_OPENSSL=OFF，以本机 HTTP 运行。原服务语音模板会覆盖自定义提示词，并在最新用户消息只有音频时省略文字历史，评测适配器因此把既有历史作为带标记的上下文放到系统消息，随后传入原始音频。

初轮音频字段适配错误，以及模板覆盖下的调试输出另存为历史记录。正式结果取修正后两轮。Qwen 的诊断矩阵使用官方音频采样默认值，提高音频长度上限，并记录 EOS 结束标记，早期受限长配置影响的输出另存。其后又以官方要求的固定系统提示词复核，将 Kitty 的应用要求放到用户上下文，检查语音输出。

## 已确认的问题

现有链路的英语识别、偏好和身份规则有效。中文词义的文字能正确给出，但当前英语 Kokoro 在这些 WAV 中反复读出 “Chinese letter”，无法正常播报中文。三条中文输入均因识别置信度不足被拒绝，无法进入对话。cherry 的“中文词义加英文例句”请求漏掉了例句。

MiniCPM 能生成中文音频，但英语提问中文词义时常回答 “Peach means peach in Chinese”。两轮都把喜欢梨推成了最喜欢梨，中文问年龄时两轮都回答六岁。偏好更正为 grapes、黑色笔、邀请、虚构人物与换题的回答较稳定。

MiniCPM 另做一秒一帧的全双工实验。确认参考音频路径有效后，官方自带样本可以产生说话帧，合成动物问答也能响应。在用户说“停止讲动物，改聊音乐”后仍继续介绍动物，未在这条样本中完成要求的打断与转向。附和样本继续回答。这里没有给出现场扬声器回声条件下的打断成功率。

本轮适合判断当前 Mac 的试用方向。真实儿童口音、背景噪声和长时间连续对话仍需独立测试。

## Qwen 的音频兼容性复核

在 Transformers 5.22.1 / Torch 2.15.0 下跑了 30 次文字与音频输出诊断，全部以 EOS 结束，但较长回复的实际波形振幅异常低，独立转写经常只得到 Thank you 或标点。其文字中能给出中文释义，同时仍出现喜欢梨升级为最喜欢梨、中文年龄回答 100 岁。该矩阵自定义了系统提示词，未纳入主质量排名。

随后用 Transformers 4.53.3 和官方固定系统提示词复核，5.94 秒的样本波形 RMS 约 0.00117，仍未还原应有内容。对相同问题、同一官方提示词及同一结束标记，仅将 Token2Wav 声码器转到 CPU 后，波形 RMS 恢复到约 0.0731，独立转写也能还原 AI 身份回答。三条 CPU 回退样本覆盖身份、中文桃子释义和邀请句，分别等待 24.4、28.3、15.6 秒才取得完整波形。

这些结果把本机问题定位到当前 Token2Wav 的 MPS 运行路径，不能据此推断 NVIDIA 流式部署的表现。Qwen 的诊断矩阵波形返回中位数为 7.72 秒，但因多数波形未通过内容核验，不把该值列为有效首音指标。

## 内存与试用建议

现有链路的语音工作进程报告 Parakeet 活跃 MLX 内存约 0.786 GB，Kokoro 约 0.165 GB，Ollama 报告 3B 模型约 2.155 GB，加起来约 3.11 GB，另有缓存与运行开销。MiniCPM 音频对话进程采样 RSS 峰值约 11.23 GB。Qwen MPS 诊断报告 driver 分配最高约 14.35 GB。这些分别来自模型活跃内存、进程 RSS、Metal driver，口径不同，不作为同口径总内存排名。

当前优先处理现有链路的双语识别与双语合成，并修复复合词义请求漏例句的问题。MiniCPM 适合继续作为全双工实验分支，后续要先提高偏好、身份与打断的可靠性。Qwen 在这台 Mac 上需要先解决声码器兼容和流式返回，再讨论替换价值。

原始结果、诊断记录和波形路径在 evals/omni_voice/results.json。固定权重版本、输入哈希、原服务源文件哈希、MiniCPM 本地适配补丁均已保留。测试结束后本地服务健康、无活跃会话，3B 模型已重新预热。
